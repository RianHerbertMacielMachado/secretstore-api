Visão Geral da Arquitetura

Entenda como as 3 peças do sistema se conectam

💡
O sistema tem 3 componentes principais:
  • API (Backend) — o "cérebro" que gerencia autenticação, licenças e dados
  • Panel Admin (Frontend Web) — o painel onde você gerencia clientes, módulos e licenças
  • Programa (.exe) — o aplicativo que roda no PC dos clientes e se comunica com a API
🔄 Como o sistema funciona
👨‍💼 Você (Admin)
gerencia clientes
→
🌐 Panel Admin
interface web
→
⚙️ API (Railway)
processa tudo
←
💻 Programa .exe
PC dos clientes

O Panel Admin e o Programa .exe ambos conversam com a mesma API. A API é o ponto central que valida logins, verifica licenças e controla quais módulos cada cliente pode usar.

⚙️ API Backend

Node.js + Express + PostgreSQL. Roda no Railway 24h. Gerencia autenticação, sessões, permissões e logs. Porta 3001.

🌐 Panel Admin

Interface web para o administrador. Cadastra clientes, define módulos permitidos, reseta senhas, visualiza logs. Roda no Railway ou Vercel.

💻 Programa .exe

Electron + Python. Roda no PC do cliente. Faz login via API, verifica permissões e executa os 5 módulos (mapas, veículos, roupas, peds, weapons).

Glossário — Termos Técnicos Explicados

Leia isso antes de começar se nunca fez deploy

🚂 Railway
Serviço de hospedagem na nuvem. Seu código roda em servidores deles 24h. Plano gratuito com $5/mês de crédito. É onde a API e o Panel Admin vão ficar.
🐘 PostgreSQL
Banco de dados gratuito e profissional. Guarda todos os dados: clientes, senhas, módulos, logs de acesso. O Railway cria e gerencia para você automaticamente.
🔑 JWT (Token)
Uma "pulseira digital" que prova que alguém está logado. Quando o cliente faz login, recebe um token. A cada ação, mostra o token para provar que tem acesso.
🌍 Variável de Ambiente
Configurações sensíveis (senhas, URLs) guardadas fora do código. Ficam no servidor e só o programa consegue ler. Mais seguro que colocar senhas no código.
📦 API (Application Programming Interface)
O "garçom" entre o programa/painel e o banco de dados. Recebe pedidos (login, listar módulos), consulta o banco e devolve a resposta.
🏗️ Deploy
O processo de colocar o código na internet. Você envia para o GitHub, o Railway pega de lá e faz rodar em um servidor público.
💻 Electron
Tecnologia que permite criar programas de computador (.exe) usando HTML, CSS e JavaScript. O programa SecretStore Organizer é feito com Electron.
🐍 PyInstaller
Ferramenta que transforma scripts Python (.py) em executáveis (.exe) independentes. Os 5 módulos do programa são compilados assim.
🔐 DATABASE_URL
Endereço completo do banco de dados com usuário e senha embutidos. O Railway gera automaticamente quando você cria o PostgreSQL.
🐙 GitHub
"Google Drive" para código. Guarda o histórico de todas as alterações. O Railway busca o código daqui para fazer o deploy.

Etapa 6 — Configurar Variáveis de Ambiente da API

A etapa mais importante — sem isso a API não funciona

📍 Como adicionar variáveis no Railway
Clique no serviço "secretstore-api" no painel do projeto
Clique na aba "Variables" no menu da esquerda
Clique em "+ New Variable" para cada variável

Ou use "Raw Editor" para colar todas de uma vez no formato NOME=valor.

Preencha o Nome (exatamente como está) e o Valor
⚙️ Variáveis obrigatórias do serviço API
PORT
obrig.›
Porta onde a API escuta. Sempre 3001 para este projeto.
3001
NODE_ENV
obrig.›
Modo de execução. Sempre production no Railway.
production
DATABASE_URL
obrig.›
String de conexão com o banco PostgreSQL do Railway.
postgresql://postgres:SenhaGerada@containers-us-west-XX.railway.app:5432/railway
Como obter
  1. Clique no serviço PostgreSQL no painel do projeto
  2. Aba Variables → copie DATABASE_URL
  3. Cole aqui
JWT_SECRET
obrig.›
Chave secreta para gerar tokens de autenticação. Deve ser longa e aleatória (64+ caracteres).
Como gerar
  1. No terminal: node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
  2. Ou online: acesse generate-secret.vercel.app/64
  3. Copie o resultado de 64 caracteres e cole como valor
JWT_EXPIRES_IN
obrig.›
Quanto tempo o token do cliente (programa .exe) dura antes de expirar.
7d

7d = 7 dias. Outras opções: 24h, 30d, 1h

JWT_ADMIN_EXPIRES_IN
obrig.›
Quanto tempo o token do administrador (panel admin) dura.
24h

24h = 24 horas. Mais curto por segurança.

ADMIN_EMAIL
obrig.›
E-mail do administrador padrão. Será criado no primeiro seed do banco. Use para fazer login no Panel Admin.
admin@secretstore.com

Pode ser qualquer e-mail — é apenas para login no painel. Não precisa ser e-mail real.

ADMIN_PASSWORD
obrig.›
Senha do administrador padrão. Use uma senha forte — mínimo 8 caracteres com letras, números e símbolos.
MinhaSenhaForte@2025
🔒
Use uma senha forte! Quem tiver essa senha controla todo o sistema. Nunca use "123456" ou "admin".
FRONTEND_URL
obrig.›
URL do Panel Admin. Necessário para o CORS (permitir que o painel web acesse a API).
https://secretstore-panel-production.up.railway.app
Como obter
  1. Você vai pegar esta URL na Etapa 8 ao configurar o Panel Admin
  2. Pode adicionar depois — ou coloque um valor temporário e corrija depois
  3. Sem barra no final! ✅ https://algo.railway.app ❌ https://algo.railway.app/
🎲 Gerador Rápido de JWT_SECRET

Clique no botão para gerar uma chave aleatória segura:

💡
Dica — "Raw Editor" para colar tudo de uma vez: No Railway, na aba Variables, procure o botão "Raw Editor" ou "Bulk Import". Você pode colar todas as variáveis no formato abaixo de uma só vez:
formato para "Raw Editor" — cole tudo de uma vez
PORT=3001
NODE_ENV=production
DATABASE_URL=COLE_A_URL_DO_POSTGRESQL_AQUI
JWT_SECRET=COLE_O_SECRET_GERADO_AQUI
JWT_EXPIRES_IN=7d
JWT_ADMIN_EXPIRES_IN=24h
ADMIN_EMAIL=admin@secretstore.com
ADMIN_PASSWORD=SuaSenhaForte@2025
FRONTEND_URL=https://URL-DO-PANEL.up.railway.app

Etapa 10 — Configurar a URL no Programa (.exe)

Apontar o programa para a API correta antes de compilar

💡
O que fazer aqui: Abrir o arquivo api-client.js no código do programa e trocar a URL placeholder pela URL real da sua API (a mesma que você gerou na Etapa 5).
1

Abra a pasta do programa no seu editor de código

É a pasta secretstore-organizer — o projeto Electron.

2

Abra o arquivo api-client.js

Está na raiz da pasta do projeto. Procure a linha com a URL placeholder:

api-client.js — linha ~3
// api-client.js const API_BASE_URL = 'https://SEU-PROJETO.up.railway.app'; ↑ TROQUE ESTA URL!
3

Substitua pela URL real da API

api-client.js — ANTES
const API_BASE_URL = 'https://SEU-PROJETO.up.railway.app';
api-client.js — DEPOIS (exemplo)
const API_BASE_URL = 'https://secretstore-api-production.up.railway.app';
🚨
Regras da URL:
  • Deve começar com https://
  • NÃO pode ter barra / no final
  • Deve ser a URL da API, não do Panel Admin
  • Se errar, o programa vai mostrar "Sem conexão" ao abrir
4

Salve o arquivo (Ctrl+S)

Pronto! Agora o programa sabe para onde enviar as requisições de login e verificação de módulos.

Etapa 12 — Testar Todo o Sistema

Verificar que API, Panel e Programa funcionam juntos

1

Teste a API (já feito na Etapa 7)

Acesse https://SUA-URL-API.railway.app/health — deve retornar JSON com "status": "online".

2

Teste o Panel Admin

Acesse a URL do Panel Admin no navegador

Crie um cliente de teste:

Menu "Clientes" → "Novo Cliente" → preencha e-mail, nome, senha temporária e marque os módulos permitidos (ex: mapas, veículos).

3

Teste o Programa (.exe)

Abra o programa SecretStore-Organizer-2.1.0.exe
A tela de login deve aparecer (sem erro "Sem conexão")

4

Verificar no Panel que o login apareceu

Volte ao Panel Admin → seção "Logs" ou na página do cliente — deve mostrar o login registrado com data/hora e device ID.

Problemas Comuns e Como Resolver

Se algo deu errado, encontre seu problema aqui

🔍
Como ver os logs de erro: No Railway, clique no serviço com problema → aba Deployments → clique no deploy → View Logs. Leia as últimas linhas em vermelho.
!

Programa mostra "Sem conexão" ao abrir

Causa: A URL em api-client.js está errada, ou a API não está rodando.

  1. Abra o navegador e acesse https://SUA-URL-API.railway.app/health
  2. Se retornar JSON → a API está OK. O problema é na URL do programa.
  3. Se der erro → a API não está rodando. Verifique os logs no Railway.
  4. Confirme que a URL em api-client.js é exatamente igual à URL da API no Railway
  5. Confirme que começa com https:// e NÃO tem barra no final
  6. Após corrigir, compile novamente (Etapa 11)
!

Panel Admin mostra tela branca ou "Network Error"

Causa: A variável NEXT_PUBLIC_API_URL está errada ou faltando no serviço do panel.

  1. Vá ao serviço do panel no Railway → Variables
  2. Verifique se NEXT_PUBLIC_API_URL existe e aponta para a URL da API (não do panel!)
  3. Deve começar com https:// e não ter barra no final
  4. Após corrigir, aguarde o redeploy automático
!

Erro CORS — "Access to fetch has been blocked"

Causa: A variável FRONTEND_URL no serviço da API não corresponde à URL do panel.

  1. Vá ao serviço da API → Variables → FRONTEND_URL
  2. O valor deve ser exatamente a URL do panel (com https, sem barra final)
  3. Se você mudou o domínio do panel, atualize esta variável na API
  4. Após atualizar, o serviço reinicia automaticamente
!

Deploy da API falha — "Cannot find module" ou "DATABASE_URL is required"

Causa: Variáveis de ambiente não configuradas ou com valor errado.

  1. Nos logs, identifique qual variável está faltando
  2. Vá em Variables da API e confirme que todas da Etapa 6 existem
  3. Verifique se não tem espaços extras no início ou final dos valores
  4. Após corrigir, clique em "Redeploy" no menu do serviço
!

Login no programa retorna "Credenciais inválidas" mesmo com senha correta

Causa: O cliente pode não existir no banco, ou a senha foi hasheada incorretamente.

  1. No Panel Admin, verifique se o cliente existe na lista
  2. Confirme que o status é "ativo" (não "bloqueado" ou "inativo")
  3. Tente fazer um "Reset de senha" pelo Panel → defina nova senha → tente novamente
  4. Se o problema persistir, verifique nos logs da API se a requisição está chegando
!

'pyinstaller' não reconhecido ao rodar o build.bat

Causa: Python ou PyInstaller não está no PATH do sistema.

  1. Instale o Python de python.org — marque "Add Python to PATH" durante a instalação
  2. Feche e reabra o terminal após instalar
  3. Execute: python -m pip install pyinstaller
  4. Teste: python -m PyInstaller --version — deve mostrar um número
  5. O build.bat já usa python -m PyInstaller ao invés de pyinstaller direto, então deve funcionar após instalar
!

Programa funciona no meu PC mas não no PC do cliente

Causa: O antivírus do cliente pode estar bloqueando, ou falta o runtime.

  1. Peça para o cliente adicionar uma exceção no antivírus para o .exe
  2. Confirme que o PC do cliente tem conexão com internet (o programa precisa para fazer login)
  3. Se o PC não tem internet, o programa pode funcionar offline por 30 dias após o primeiro login (funcionalidade de cache)
  4. Verifique se o firewall corporativo não está bloqueando o acesso a *.railway.app
!

Railway mostra "Out of credits" ou "Service sleeping"

Causa: O plano gratuito do Railway tem limite de $5/mês.

  1. Monitore o uso em Settings → Usage no painel do projeto
  2. Para um sistema leve como este, $5/mês costuma ser suficiente
  3. Se precisar mais, faça upgrade para o plano Hobby ($5/mês fixo + consumo)
  4. Dica: se estiver apenas testando, pause os serviços quando não estiver usando
💬
Problema diferente? Copie a mensagem de erro exata dos logs do Railway e envie. Quanto mais detalhes, mais rápido a resolução.
